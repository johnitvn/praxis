# Workflow: Plan

Create an actionable plan to achieve a goal.

## Purpose

Planning transforms a goal into a sequence of actions that can be executed. It bridges the gap between "what should we achieve?" and "how do we achieve it?"

## When to Use

- You have a goal but not a clear path to achieve it
- The goal requires coordinating multiple actions, people, or resources
- There are dependencies between actions
- Resources are constrained
- Uncertainty about the future requires contingencies

## Workflow

### Phase 1: Define the Goal

**Goal**: State clearly what you're trying to achieve.

1. **What is the objective?** Make it specific and measurable
2. **Why does it matter?** The purpose behind the goal
3. **What are the constraints?** Budget, time, resources, quality
4. **What does success look like?** How will you know you've achieved it?

**Methods**: Goal definition, problem framing

### Phase 2: Decompose

**Goal**: Break the goal into manageable components.

1. **What are the major workstreams?**
2. **What are the sub-goals?**
3. **What are the deliverables?**
4. **Decompose until each component is actionable**

**Methods**: Decomposition, hierarchical planning, work breakdown structure

### Phase 3: Sequence

**Goal**: Order the work based on dependencies and priorities.

1. **What depends on what?** Map dependencies
2. **What is the critical path?** The sequence that determines the overall duration
3. **What can be parallelized?** Independent workstreams
4. **What must come first?** Prerequisites and foundations

**Methods**: Dependency analysis, critical path method, scheduling

### Phase 4: Estimate

**Goal**: Estimate effort, duration, and resource needs for each component.

1. **How long will each component take?**
2. **What resources does each need?** People, tools, budget
3. **What are the uncertainties in estimates?**
4. **Use reference classes**: How long have similar efforts taken?

**Methods**: Reference class forecasting, estimation, uncertainty quantification

### Phase 5: Allocate Resources

**Goal**: Assign resources to components.

1. **Match resources to needs**
2. **Identify bottlenecks**: Where is demand exceeding supply?
3. **Resolve conflicts**: When two things need the same resource
4. **Build in slack**: Plans always take longer than estimated

**Methods**: Resource planning, constrained optimization, leveling

### Phase 6: Identify Risks

**Goal**: Anticipate what could go wrong.

1. **What are the risks to the plan?**
2. **What are the highest-impact risks?**
3. **What are the early warning signs?**
4. **What are the mitigation strategies?**

**Methods**: Risk analysis, premortem, contingency planning

### Phase 7: Build Contingencies

**Goal**: Prepare for the unexpected.

1. **What if key assumptions are wrong?**
2. **What if a critical resource is unavailable?**
3. **What if a dependency is delayed?**
4. **Build contingency plans for the top risks**

**Methods**: Contingency planning, scenario planning, decision trees

### Phase 8: Communicate

**Goal**: Ensure everyone understands the plan.

1. **Who needs to know what?**
2. **What are the key milestones?**
3. **What are the expectations?**
4. **How will progress be tracked?**

**Methods**: Communication, stakeholder management

### Phase 9: Execute and Monitor

**Goal**: Execute the plan and track progress.

1. **Track progress against milestones**
2. **Monitor for early warning signs**
3. **Adjust the plan as reality unfolds**
4. **Communicate changes**

**Methods**: Monitoring, adaptive planning, escalation

## Common Failure Modes

- **Planning fallacy**: Underestimating time and resources systematically
- **Over-planning**: Creating overly detailed plans that become obsolete immediately
- **Under-planning**: Starting without sufficient planning
- **Ignoring dependencies**: Not accounting for what depends on what
- **No contingencies**: Assuming everything will go according to plan
- **Plan rigidity**: Not adapting the plan when circumstances change
- **Resource overcommitment**: Assigning more work than resources can handle
