# Escalation

Know when and how to escalate reasoning.

## Purpose

Escalation is recognizing that the current reasoning approach is insufficient and moving to a more powerful or appropriate approach. Escalation is not failure — it's adaptive reasoning.

## When to Escalate

### 1. Method Insufficiency
The current method is not producing adequate results.
- **Signal**: Results are not converging, assumptions are violated, limitations are blocking progress
- **Action**: Escalate to a more powerful method or add complementary methods

### 2. Stake Escalation
The stakes are higher than initially assessed.
- **Signal**: New information reveals greater consequences, more stakeholders affected, more irreversible
- **Action**: Escalate depth, add adversarial review, add verification

### 3. Complexity Escalation
The problem is more complex than initially understood.
- **Signal**: Hidden interdependencies, emergent behavior, second-order effects
- **Action**: Escalate from simple methods to systems thinking, from single method to composition

### 4. Uncertainty Escalation
Uncertainty is higher than initially assessed.
- **Signal**: Key assumptions are uncertain, evidence is weaker than expected, methods disagree
- **Action**: Escalate to probabilistic methods, add uncertainty quantification, gather more information

### 5. Disagreement Escalation
Methods or stakeholders disagree.
- **Signal**: Parallel methods produce conflicting results, stakeholders have incompatible views
- **Action**: Escalate to adversarial review, dialectic, structured reconciliation

## Escalation Paths

| From | To | Trigger |
|------|----|---------|
| Pattern matching | Structured method | Problem is not routine |
| Single method | Method composition | Problem crosses boundaries |
| Low depth | Higher depth | Stakes or complexity increase |
| Deterministic | Probabilistic | Uncertainty is material |
| Independent analysis | Systems thinking | Interconnections matter |
| Point estimate | Uncertainty quantification | Precision matters |
| Individual reasoning | Adversarial review | Stakes are high |
| Current knowledge | Information gathering | Knowledge gaps are material |
| Self-contained | Escalation to user | Agent cannot resolve alone |

## Escalation Decision Flow

```
Current approach
│
├─ Is it working?
│   ├─ Yes → Continue
│   └─ No → Why not?
│       ├─ Method wrong → Select different method
│       ├─ Missing information → Gather information
│       ├─ Problem too complex → Compose methods
│       └─ Beyond capability → Escalate to user
│
├─ Are stakes higher than thought?
│   ├─ Yes → Escalate depth + verification
│   └─ No → Continue
│
└─ Is confidence too low?
    ├─ Yes → Can more reasoning help?
    │   ├─ Yes → Escalate method
    │   └─ No → Escalate to user (document uncertainty)
    └─ No → Continue
```

## When NOT to Escalate

- **The current method is working**: Don't escalate just because a more powerful method exists
- **The cost of escalation exceeds the benefit**: More powerful methods are usually more expensive
- **Time is critical**: Escalation takes time; sometimes a good-enough answer now is better
- **The problem doesn't warrant it**: Low stakes, reversible decisions don't need escalation

## Common Failure Modes

- **Escalation reluctance**: Not escalating when you should (pride, inertia, not noticing)
- **Escalation panic**: Escalating too quickly without giving the current method a fair chance
- **Always escalate**: Defaulting to the most powerful method for every problem
- **Escalation without adaptation**: Changing the label but not actually changing the approach
